# Конференции.РФ

Готовый учебный веб-проект по приложенным заданиям: выбор помещений для конференций, регистрация, личный кабинет, отправка заявок и работа администратора. Реализация на **PHP + SQL + HTML + CSS + JavaScript**. Данные сохраняются в настоящей базе, а не в localStorage.

## Что входит

- Приветственная страница с тремя форматами помещений и порядком работы.
- Регистрация с проверкой уникальности логина и всех полей на сервере.
- Авторизация с сообщением об ошибке, завершение сеанса.
- Создание заявки: помещение, дата и время по Москве, способ оплаты.
- Личный кабинет: только собственные заявки, фильтры, отзывы после завершения.
- Панель администратора: все заявки, контакты пользователей, поиск, фильтры и смена статуса.
- Шесть адаптивных страниц, в том числе дополнительный личный кабинет из PDF.
- SQL-схемы, CLI-установщик, ER-диаграмма, инструкция и контрольные сценарии.

Помещения «Горизонт», «Диалог», «Панорама», их вместимость и оснащение — демонстрационные данные. В исходниках задания названия и характеристики конкретных площадок не заданы. Изображения — локальные SVG-иллюстрации; интернет для работы интерфейса не требуется.

## Требования

- PHP **8.1 или новее** с расширениями `PDO`, `pdo_mysql`, `mbstring` и `session`.
- MySQL **8.0.16+** или MariaDB **10.6+**.
- Для упрощённого варианта без MySQL: расширение `pdo_sqlite`.
- Современный браузер. Сборка Node.js, npm и Composer не нужна. Доступ к данным реализован через стандартную библиотеку PDO, серверный код разделён на классы.

## Запуск с MySQL — основной вариант

1. Распакуйте проект. Запустите MySQL в OpenServer, XAMPP либо отдельно.
2. Создайте базу через phpMyAdmin или консоль SQL:

   ```sql
   CREATE DATABASE konferencii CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

3. Скопируйте `app/config.example.php` в `app/config.php`. Укажите свой логин, пароль, адрес и порт MySQL. Параметр `driver` оставьте равным `mysql`. Файл с реальными паролями не включайте в репозиторий.
4. Откройте терминал **в папке проекта** и выполните:

   ```bash
   php database/setup.php
   ```

   Установщик создаст таблицы, три помещения и администратора. Повторный запуск не удаляет данные и не создаёт дубликаты. Если таблицы уже существуют, установщик предполагает, что они соответствуют этой версии схемы.
5. Для локального просмотра запустите:

   ```bash
   php -S 127.0.0.1:8000 -t public
   ```

6. Откройте **http://127.0.0.1:8000**.

Если команда `php` не найдена, используйте терминал OpenServer или полный путь к исполняемому файлу, например `C:\xampp\php\php.exe`. Во втором случае замените `php` на этот путь в обеих командах.

### OpenServer / Apache

Можно вместо встроенного сервера PHP направить корневой каталог виртуального хоста (DocumentRoot) на папку `public/` проекта. Выберите PHP 8.1+, перезапустите сервер и откройте назначенный локальный домен.

В XAMPP также можно распаковать проект в `htdocs/konferencii`, выполнить установщик и перейти на `http://localhost/konferencii/public/`. Для этого варианта включены защитные `.htaccess`. Предпочтительный вариант для публикации — отдельный DocumentRoot на `public/`, чтобы каталог с конфигурацией не был доступен по HTTP.

### Импорт SQL через phpMyAdmin

Вместо автоматического создания таблиц можно импортировать `database/schema.sql` в **пустую** выбранную базу. После импорта всё равно выполните `php database/setup.php`: он добавит помещения и администратора с корректным хешем пароля.

## Быстрый запуск без MySQL

SQL-база SQLite предусмотрена как дополнительный режим:

1. Скопируйте `app/config.example.php` в `app/config.php`.
2. Установите `'driver' => 'sqlite'`.
3. Включите PHP-расширения `pdo_sqlite` и `mbstring`.
4. Выполните `php database/setup.php`, затем `php -S 127.0.0.1:8000 -t public`.

Файл базы появится в `var/konferencii.sqlite`. Каталог `var/` должен быть доступен PHP на запись и находиться за пределами публичного каталога.

## Учётная запись администратора

| Поле | Значение |
|---|---|
| Логин | `Conf2027` |
| Пароль | `Demo77` |

Это реквизиты **из задания**. Администратор входит через обычную страницу входа и автоматически попадает в панель управления. Исключение для короткого пароля действует только при установке этой учебной записи: пользовательская регистрация требует минимум 8 символов.

Обычного пользователя создайте через «Регистрация». Его данные и заявки сохраняются в выбранной БД. Пустой кабинет после установки — ожидаемое поведение: фиктивных пользователей и заявок в поставке нет.

## Как проверить работу

1. Зарегистрируйте пользователя с логином от 6 символов, паролем от 8 символов, ФИО кириллицей, телефоном `8(999)123-45-67` и корректным email.
2. Войдите, создайте заявку на будущую дату. Убедитесь, что она появилась со статусом «Новая».
3. Выйдите. Войдите как `Conf2027`, найдите заявку и измените статус на «Мероприятие назначено».
4. После мероприятия измените статус на «Завершено».
5. Снова войдите пользователем и оставьте отзыв с оценкой 1–5. Отзыв появится в карточке пользователя и в панели администратора.

Подробный список проверок: `docs/TESTING.md`.

## Правила приложения

- Логин: 6–50 символов, латиница и цифры, уникальность без учёта регистра.
- Пароль пользователя: минимум 8 символов, максимум 72 байта (ограничение bcrypt). Пароль не обрезается и не выводится обратно в форме.
- ФИО: кириллица и пробелы, максимум 150 символов.
- Телефон: точно `8(XXX)XXX-XX-XX`. JavaScript также преобразует полный ввод `+7…` при выходе из поля.
- Email: проверяется сервером, максимум 190 символов.
- Дата и время начала: в будущем, часовой пояс `Europe/Moscow`.
- Оплата: очное посещение или СБП. Это выбор способа оплаты: платёжный шлюз и реальный перевод денег в задании не предусмотрены.
- Статусы движутся вперёд: «Новая» → «Мероприятие назначено» → «Завершено». Возврат назад не предусмотрен.
- Заявка — запрос на согласование. Автоматический учёт занятости и длительности мероприятия не реализован, поскольку длительность не задана; пересечения проверяет администратор.
- Один отзыв на собственное завершённое мероприятие. Текст 10–2000 символов, оценка 1–5. До завершения сервер отклонит отзыв, даже при ручной отправке HTTP-запроса.

## Структура

```text
app/
  config.example.php  пример подключения
  bootstrap.php       сессия, заголовки, вспомогательные функции
  Database.php        подключение PDO и подготовленные запросы
  Auth.php            регистрация, вход, текущий пользователь
  Booking.php         заявки, статусы, отзывы, поиск
  views.php           HTML-шаблоны шести страниц
public/
  index.php           маршрутизация, действия и проверка доступа
  assets/style.css    единая дизайн-система и адаптивная вёрстка
  assets/app.js       интерактивность форм и мобильная навигация
  assets/*.svg        собственные локальные иллюстрации
  .htaccess          настройки Apache
app/config.php        создаётся пользователем, не хранится в Git
database/
  schema.sql          таблицы MySQL / MariaDB
  schema.sqlite.sql   альтернативная схема SQLite
  setup.php           создание схемы и начальных данных
docs/
  ER-diagram.svg      диаграмма связей
  ER-diagram.mmd      редактируемый исходник Mermaid
  TESTING.md          проверка и ограничения
  DESIGN.md           палитра, компоненты, соответствие заданию
  project-history.bundle  локальная история Git
tests/smoke.php        25 изолированных проверок логики на SQLite
```

Страницы открываются через `index.php?page=home|login|register|booking|dashboard|admin`. Проект работает и в подкаталоге — абсолютных ссылок на корень домена нет.

## Защита данных

Применены `password_hash` / `password_verify`, подготовленные SQL-запросы, серверная валидация, CSRF-токены для всех POST-действий, экранирование HTML, смена ID сессии при входе и проверки владельца заявки. Вход ограничен восемью неуспешными попытками на сочетание логина и IP за 15 минут. Рабочие ошибки БД записываются в журнал сервера; браузер не получает SQL и пароли.

При размещении в интернете настройте HTTPS, отдельную учётную запись БД с нужными правами и замените учебный пароль администратора. Встроенный сервер `php -S` предназначен для локальной проверки.

## Git

В архиве приложена история двух коммитов в `docs/project-history.bundle`. При необходимости восстановите репозиторий:

```bash
 git clone docs/project-history.bundle konferencii-repo
```

Либо создайте свой репозиторий из исходников и отправьте его на выданный учебный сервер. Адрес индивидуального удалённого репозитория в материалах отсутствовал, поэтому отправка на него не выполнялась.

## Проверка в среде разработки

В дополнительной среде PHP WebAssembly выполнены 25 проверок серверной логики на SQLite: регистрация, уникальность логина, вход, валидация заявки, изоляция пользователей, статусы, отзывы, поиск, счётчики, экранирование и ограничение входа. Проверен запуск установщика и генерация всех шести HTML-страниц без ошибок PHP. PHP-файлы также прошли синтаксический разбор Tree-sitter PHP; JavaScript — `node --check`. Связи и ограничения SQL проверены выполнением схемы SQLite.

MySQL-сервер и обычный PHP в данной среде отсутствуют. Работа именно с MySQL и визуальная проверка в браузере на мобильном и настольном экране здесь не выполнялись. Перед демонстрацией запустите проект в своём PHP/MySQL-окружении и выполните сценарии из `docs/TESTING.md`.
